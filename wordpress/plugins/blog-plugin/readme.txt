Private foundation for generating and reviewing ZebraCode blog content with AI.

== Current scope ==

The current foundation provides:

* An isolated, installable WordPress plugin boundary.
* A namespaced bootstrap and activation/deactivation hooks.
* An admin settings page under Blog AI.
* Server-side storage for an OpenAI-compatible endpoint and model.
* WordPress 7.0+ Connectors integration for the server-side API key, with environment, constant, and legacy-setting fallbacks.
* A custom `{$wpdb->prefix}ai_generation_logs` table for prompts, responses, models, users, statuses, and timestamps instead of option-based activity history.
* Secure REST routes for direct generation, SSE streaming, bulk enqueueing, and generation-history writes.
* A React-powered AI Studio that consumes `ReadableStream` chunks with `TextDecoder` and saves completed responses through a second REST request.
* Action Scheduler integration for bulk work when it is available, with WP-Cron fallback.
* Feature switches that keep disabled integrations from registering hooks or assets.
* Optional Gutenberg, Elementor, and WooCommerce integration modules.
* A provider contract that future generation and review workflows can use.
* A replaceable service-provider registry for OpenAI-compatible and Gemini adapters.
* A Tailwind CSS v4 source and compiled admin stylesheet for the plugin screens.
* A server-side OpenAI-compatible request adapter with bounded options and timeouts.
* Structured article JSON validation and normalization.
* A draft-only Generate article form with nonce and capability checks.
* Storage of generated content as a WordPress Draft with review metadata.
* A non-generating Provider connection test from Settings.
* A real Draft library and bounded activity log.
* A public read-only REST endpoint for published generated posts.
* A WP-Cron-backed generation queue with one retry before failure.
* A native Google Gemini provider adapter.
* Provider switching that pre-fills the matching Gemini/OpenAI endpoint and model.
* A server-side model list picker for the selected provider.
* A connection test that probes both `/models` and the selected model's generation endpoint.
* Persian-first generation instructions with a validation guard for non-Persian drafts.
* A Prompt lab for manually testing prompts without creating a post or queue job.
* A formatting fallback that converts provider Markdown into readable WordPress headings, paragraphs, lists, and code blocks.
* SEO, AEO, and GEO generation rules for search intent, direct answers, entity clarity, question headings, FAQs, and quote-ready paragraphs.
* Local audit signals for direct-answer blocks, question headings, and scannable technical structure.
* SEO quality columns in the WordPress Posts list with score, AEO, GEO, FAQ, and link signals.
* A low-score "Refresh safely" action that queues a separate review draft instead of overwriting the original post.
* Optional featured-image generation for new article drafts using the configured provider key and a separate image-capable model.
* Protected-fragment refreshes that preserve existing images, links, code, tables, embeds, shortcodes, Gutenberg blocks, featured images, and taxonomies when the provider returns a valid token-preserving response.
* Source hash and modified-time checks that mark a refresh stale when the original article changes while the job is running.
* Locale-aware Persian/English admin UI with RTL shell direction and LTR technical fields.
* Server-side DNS, WordPress HTTP, and native PHP cURL diagnostics for shared hosting.

The next implementation slices are candidate diff/approval, revision-backed apply, analytics integrations, and deployment automation around the static blog build.

== REST endpoint ==

Published generated posts are available to the static frontend at:

`/wp-json/zebracode-blog/v1/posts?per_page=100`

Only published posts marked as generated by this plugin are returned. Drafts, provider credentials, and private settings are never exposed by this endpoint.

Authenticated admin routes use the `X-WP-Nonce` header and `current_user_can()` checks:

* `POST /wp-json/zebracode-blog/v1/ask` for a buffered provider response.
* `POST /wp-json/zebracode-blog/v1/stream-ai` for `text/event-stream` output.
* `POST /wp-json/zebracode-blog/v1/logs` to save the completed browser stream.
* `POST /wp-json/zebracode-blog/v1/bulk` to enqueue bounded background jobs.

== Gemini setup ==

Use these values in Blog AI > Settings, then add the API key in Settings > Connectors on WordPress 7.0+:

* Provider: Google Gemini (Generative Language API)
* API base URL: `https://generativelanguage.googleapis.com/v1beta`
* Model: `gemini-flash-latest`
* API key: a newly generated Gemini API key, stored by the WordPress Connectors screen

The Gemini adapter sends the key only in the server-side `X-goog-api-key` header. Revoke any key that has been shared publicly before using the plugin.

== Admin CSS development ==

The committed `assets/admin.css` file is ready for WordPress. To rebuild it after changing the Tailwind source:

`npm ci`

`npm run build:css`

== Development location ==

The source lives in this repository under:

`wordpress/plugins/blog-plugin/`

When installed in WordPress, copy this folder to:

`wp-content/plugins/blog-plugin/`

Future independent plugins should be siblings under `wordpress/plugins/`.

== Security notes ==

* Provider requests will be made server-side through WordPress HTTP APIs.
* API keys must never be placed in frontend JavaScript or public Next.js environment variables. On WordPress 7.0+, manage the active key from Settings > Connectors; older WordPress versions keep using the legacy plugin setting.
* The plugin requires PHP 8.0 or newer for the modular streaming architecture.
* The plugin will save generated articles as drafts until an explicit editorial workflow is implemented.

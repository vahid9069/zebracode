# وبلاگ فارسی ZebraCode

یک پروژه مستقل **Next.js App Router** در پوشه `blog`؛ با محتوای محلی به‌عنوان fallback، خروجی استاتیک و امکان دریافت محتوای منتشرشده از REST API پلاگین وردپرس در زمان build. رابط فارسی و راست‌به‌چپ است؛ کدها و مثال‌های فنی چپ‌به‌راست نمایش داده می‌شوند.

## اجرا

از ریشه مخزن:

```bash
npm --prefix blog install
npm --prefix blog run dev
```

نشانی توسعه: **http://localhost:3004/blog/**

ساخت و پیش‌نمایش خروجی استاتیک:

```bash
npm --prefix blog run build
npm --prefix blog run preview
```

نشانی پیش‌نمایش: **http://127.0.0.1:3004/blog/**

سرور توسعه و پیش‌نمایش به‌صورت پیش‌فرض از یک پورت استفاده می‌کنند؛ هم‌زمان اجرا نشوند. پیش‌نمایش فقط خروجی `blog/out` را ارائه می‌کند و به فایل‌های خصوصی یا پوشه اصلی مخزن دسترسی وب نمی‌دهد. ابزارهای وب‌سایت اصلی در این پروژه اجرا نمی‌شوند؛ لینک آن‌ها به نشانی مجموعه ابزارها اشاره دارد.

## آنچه ساخته شده

- صفحه اصلی با مقاله منتخب، تصویرسازی فنی محلی، جستجوی زنده و فیلتر موضوعی.
- پنج دسته: داده و فرمت‌ها، برنامه‌نویسی، امنیت، شبکه و بهره‌وری.
- هشت مقاله نمونه کامل؛ مسیر مقاله `/blog/articles/[slug]/` و دسته `/blog/category/[slug]/`.
- صفحه مطالعه با فهرست مطالب، کد قابل کپی، جدول، نکته/هشدار، سؤال‌وجواب، منابع، ابزارهای مرتبط و مقاله‌های پیشنهادی.
- تم روشن/تیره و ذخیره ترجیح تم در همین مرورگر؛ بدون ردیابی، فرم خبرنامه نمایشی یا آمار ساختگی.
- SEO فارسی، canonical، Open Graph، `BlogPosting`، `BreadcrumbList`، FAQ schema و sitemap.
- فونت فارسی از فایل محلی موجود در مخزن اصلی استفاده می‌شود؛ Next آن را در خروجی مستقل وبلاگ بسته‌بندی می‌کند. اگر پوشه `blog` را از این مخزن جدا کردید، مسیر فونت در `src/app/layout.tsx` را به یک فونت محلی با مجوز مناسب تغییر دهید.

Next.js و React این پروژه به‌ترتیب `15.5.28` و `19.1.10` هستند. نسخه‌ها و وابستگی‌های پروژه اصلی تغییر نکرده‌اند. `node_modules`، lockfile و `.next` وبلاگ مستقل‌اند. فقط تنظیمات TypeScript و Vitest ریشه، پوشه وبلاگ را از بررسی‌های پروژه اصلی مستثنی می‌کنند تا aliasها و خروجی ساخت دو پروژه با هم تداخل نکنند.

## فایل‌های اصلی

- `src/content/`: دسته‌ها، نویسنده نمونه و مقاله‌های فارسی؛ هر مقاله فایل مجزا دارد.
- `src/lib/types.ts`: قرارداد مستقل محتوا و بلوک‌های مقاله.
- `src/lib/repository.ts`: رابط داده async؛ منبع وردپرس اختیاری است و در نبود/خطای آن داده محلی استفاده می‌شود.
- `src/lib/search.ts`: جستجوی محلی و نرمال‌سازی حروف فارسی/عربی؛ بدنه مقاله‌ها را به مرورگر وارد نمی‌کند.
- `src/lib/site.ts`: تنظیم نشانی‌ها و قالب‌بندی تاریخ/عدد فارسی.
- `src/components/ArticleCatalog.tsx`: فهرست و جستجو؛ `ArticleReader.tsx`: نمایش مقاله.
- `src/app/globals.css` و `src/styles/`: توکن‌های رنگ و استایل‌های مستقل.
- `src/app/articles/[slug]/page.tsx`: ساخت استاتیک مقاله و metadata/schema.

## وضعیت پیش‌نمایش و سئو

**این مقاله‌ها نمونه طراحی هستند.** به همین دلیل، پیش‌نمایش بنر مشخص و `noindex` دارد تا تصادفاً به‌عنوان محتوای نهایی ایندکس نشود. تاریخ‌ها و هویت تحریریه مربوط به نمونه‌اند؛ پیش از انتشار واقعی آن‌ها را بازبینی کنید.

تنظیمات عمومی استقرار را می‌توان در `blog/.env.local` قرار داد؛ نمونه زیر صرفاً آدرس عمومی است، نه اطلاعات احراز هویت:

```dotenv
NEXT_PUBLIC_BLOG_URL=https://example.com/blog
NEXT_PUBLIC_TOOLS_URL=https://example.com
NEXT_PUBLIC_BLOG_INDEXABLE=false
```

پس از جایگزین‌کردن محتوای نمونه، تأیید حقوق انتشار و بررسی دامنه نهایی، مقدار `NEXT_PUBLIC_BLOG_INDEXABLE` را `true` کنید و دوباره build بگیرید. این متغیر کنترل ایندکس پیش‌نمایش است، نه احراز هویت یا پنهان‌سازی محتوا.

`basePath` فعلی `/blog` است. روی هاست استاتیک باید **محتویات `blog/out` زیر مسیر عمومی `/blog/`** سرو شوند؛ در استقرار چندپروژه‌ای هم باید همین مسیر به خروجی وبلاگ هدایت شود. این مرحله به تنظیم هاست بستگی دارد و در سایت اصلی ادغام نشده است. در دامنه مشترک، sitemap وبلاگ را به robots/sitemap ریشه سایت معرفی کنید؛ فایل `/blog/robots.txt` جایگزین robots دامنه اصلی نیست.

## اتصال به وردپرس

پلاگین `blog-plugin` یک endpoint عمومی فقط‌خواندنی برای مقاله‌های منتشرشده دارد. برای فعال‌کردن منبع وردپرس در زمان build، متغیر server-only زیر را تنظیم کنید:

```dotenv
WORDPRESS_BLOG_API_URL=https://example.com/wp-json/zebracode-blog/v1
```

Adapter فقط `/posts?per_page=100` را می‌خواند و HTML مقاله را به بلوک‌های محدود و قابل نمایش تبدیل می‌کند. اگر endpoint در دسترس نباشد، پاسخ خالی باشد یا mapping شکست بخورد، محتوای نمونه محلی fallback می‌شود. این مقدار را با `NEXT_PUBLIC_` شروع نکنید و هرگز کلید مدیریتی در آن قرار ندهید.

چون خروجی فعلاً استاتیک است، انتشار/ویرایش/حذف مقاله به build و deploy مجدد نیاز دارد. برای خودکارسازی این کار، webhook ساخت را در CI/CD پروژه تنظیم کنید؛ این پروژه ISR یا انتشار لحظه‌ای سروری ندارد.

## بررسی‌ها

```bash
npm --prefix blog run typecheck
npm --prefix blog test
npm --prefix blog run build
```

نتیجه اجرای فعلی: **TypeScript موفق، ۹ تست موفق، build موفق با ۲۰ خروجی استاتیک**. تست‌ها هر هشت مقاله و قراردادهای جستجو/داده را پوشش می‌دهند. بررسی HTTP نیز ۱۴ صفحه اصلی/مقاله/دسته، منبع محلی فونت و CSS، metadata فارسی/RTL، noindex پیش‌نمایش، schema مقاله، sitemap و صفحه 404 را تأیید کرد.

بازکردن پیش‌نمایش در کنترل مرورگر این جلسه timeout شد و تب قبلی نیاز به توجه کاربر داشت؛ بررسی بصری دسکتاپ/موبایل و کلیک واقعی روی جستجو، تغییر تم و کلیپ‌بورد **تأییدشده محسوب نمی‌شوند**. برای بازبینی دستی، پیش‌نمایش بالا را باز کنید؛ کدهای طولانی، عرض ۳۷۵ و ۷۶۸ و ۱۴۴۰، تم تیره، نتیجه خالی جستجو، کلید Tab، پیوندهای فهرست مقاله و کپی کد را آزمایش کنید.
